Ten Prompts Ago: App Map

A short guide to where things live, following one real action from the button you click to the file your agent reads.

Snapshot of the code at commit 709424f (2 October 2026). If the code changes later, this map can drift; the files and function names are the reliable anchors.

What the app is

You log the decisions you make while building with an AI coding agent and the bugs you've already fixed, each as one sentence plus a reason. The app turns them into a CONTEXT.md you paste into your agent at the start of a session, so it stops undoing settled choices. It is one Flask page backed by one SQLite file.

  • app.py: the Flask app. Routes, form checks, and who owns which entries.
  • db.py: every SQLite query. One entries table.
  • context_export.py: turns entries into the CONTEXT.md text.
  • templates/index.html: the single page (add form, list, edit, export).
  • static/style.css and static/app.js: the Apple-style look, the Copy button, and the delete prompt.

One action, end to end: Export CONTEXT.md

This is the heart of the app, so it's the action worth knowing by heart.

A route through the code reference route

Three stops for the Export action, in the order the request travels. This route was prepared for you to follow on your own; it wasn't toured live.

  1. The button and the preview

    templates/index.html, search for id="export"

    The Export button is just a link back to the same page with ?export=1. When the page comes back with text in context, the same section shows it in <pre id="context-preview"> with Copy and Download; when there's nothing, it shows "Nothing to export yet."

    Show the snippet 
    {% if not export_open %}
  <a class="button primary" href="{{ url_for('index', export=1) }}#export">Export CONTEXT.md</a>
{% elif context %}
  <pre id="context-preview" class="preview" ...>{{ context }}</pre>
  ... Copy (data-copy-target="context-preview") and Download ...
{% else %}
  <p class="empty-export" role="status">Nothing to export yet. ...</p>
{% endif %}

  2. The route that gathers your entries

    app.py, functions index(), render_page() and download()

    render_page() loads only this visitor's entries with db.list_entries(database(), g.owner), then calls build_context(entries) only when the export is open. download() sends the same text as a file named CONTEXT.md, or sends you back to the "Nothing to export yet" message if the list is empty. g.owner is set by identify_visitor(): "local" on your machine, an anonymous cookie id on the public demo.

  3. The text your agent reads

    context_export.py, function build_context(), constants INTRO and SECTIONS

    It writes a heading and one instruction line, then "Decisions" and "Don't repeat these," skipping a group with nothing in it. Each entry becomes one line ending in its reason. as_sentence() makes sure each part ends like a sentence. It returns None for no entries, which is what triggers the empty message.

A practice to reuse

Test the riskiest assumption as soon as there's something to test it with. The whole app rests on one belief: an agent will actually follow a written CONTEXT.md. devpost/spec.md named that as the open question under "Decisions and Open Issues," and the checklist made it part of slice 2's verification, right after export first worked and before edit, delete, or hosting.

The check (devpost/context-experiment.md) gave six fresh agents a request that tempts them to add logins. With no context, both added logins. With either a notes dump or the exported file, all four named the no-login decision and asked first. That confirmed the core idea and also corrected an assumption in the original plan, that a plain dump gets ignored, which is recorded under "Revisions" in devpost/checklist.md.

On another project: write down the one assumption that would sink the idea if it were wrong, plan the cheapest check that could prove it wrong, and run it as soon as the first working slice exists. Record the result next to the plan, even when it says your plan was partly wrong.

Run it again

From the project folder, with Python 3.11 or newer:

python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
flask --app app run --debug

Then open http://127.0.0.1:5000. Run the tests with python -m pytest. The README.md also covers public demo mode and deploying with render.yaml.
